# DPG Video Viewer

Просмотр локальных видео в обычном и 360° equirectangular режиме. Файлы
обрабатываются в браузере и не отправляются на сервер. Сохранены интерфейс,
зацикленное воспроизведение без звука, плейлист, перемотка, масштабирование,
перетаскивание, fullscreen и горячие клавиши прежней версии.

Новая версия подготовлена в ветке `refactor/modular-viewer`. Переход на неё
выполняется после проверки и слияния pull request; текущий `main` продолжает
работать отдельно.

## Быстро проверить новую версию

Нужен Node.js 22 или новее. Для запуска приложения установка npm-пакетов
не требуется:

```bash
git clone --branch refactor/modular-viewer https://github.com/Nchernyshev77/DPG-Video-Viewer.git
cd DPG-Video-Viewer
npm run dev
```

Откройте http://127.0.0.1:8080 и перетащите видео в окно. Через кнопку **Code →
Download ZIP** на странице новой ветки также можно скачать проект, распаковать
его и выполнить `npm run dev` из папки проекта.

Двойной щелчок по `index.html` через `file://` не подходит: ES-модулям нужен
HTTP-сервер. Любой обычный статический хостинг, включая GitHub Pages, подходит.
Все пути относительные, поэтому приложение работает и в подпапке репозитория.

## Предзагрузка и сетевые диски

Выбранный файл по умолчанию полностью предзагружается в локальный Blob-кеш,
как в прежней версии. После предзагрузки воспроизведение и перемотка читают
копию, а не исходный файл на сетевом диске. Прогресс показан в центре экрана.
Браузер сам выбирает, хранить Blob в памяти или во временном локальном файле.

Общий лимит кеша — **2 ГБ**, а не 2 ГБ на каждый ролик. Старые, реже используемые
файлы освобождаются при достижении лимита. Повторное переключение на файл,
который ещё в кеше, не читает его заново. Неактивные файлы из плейлиста заранее
не загружаются. Удаление записи и очистка плейлиста освобождают ненужный кеш.

В панели **Info → Preload cache limit** доступны Off, 512 MB, 1 GB, 2 GB и 4 GB.
Выбор 4 GB рассчитан на компьютеры с достаточным запасом памяти. Файл больше
выбранного лимита открывается напрямую; это явно показано в Info. Для сетевого
файла такой режим снова зависит от скорости диска. Предзагрузку можно прервать
кнопкой **Open without preloading** или выбором другого файла. Ошибка кеширования
автоматически возвращает прямое чтение. Исходные файлы не меняются.

При удержании стрелок/A/D или экранной кнопки кадров следующий seek начинается
после загрузки и отрисовки предыдущего кадра. Повторы клавиши не накапливают
длинную очередь: если декодер занят, сохраняется только один повтор. Последний
кадр остаётся на экране, пока новый ещё недоступен. Предзагрузка уменьшает
зависимость от дискового ввода, но не ускоряет сам декодер на перегруженном ПК.

## Структура

| Путь                        | Назначение                                              |
| --------------------------- | ------------------------------------------------------- |
| `index.html`                | Только разметка, карта импортов и точка входа           |
| `styles/`                   | Отдельные стили основы, viewport, контролов и панелей   |
| `src/main.js`, `src/app.js` | Запуск и соединение компонентов                         |
| `src/core/`                 | Общие функции и очистка обработчиков                    |
| `src/media/playlist.js`     | Список файлов и владение object URL                     |
| `src/media/player.js`       | Жизненный цикл видео, play/pause, seek, шаг и FPS       |
| `src/media/cache.js`        | Предзагрузка выбранного файла, LRU и общий лимит кеша   |
| `src/media/metadata.js`     | Ограниченное чтение MP4/MOV/WebM/MKV метаданных         |
| `src/rendering/viewer.js`   | Three.js, режимы проекции и ресурсы GPU                 |
| `src/ui/`                   | HUD, панели, ввод и автоматическое скрытие              |
| `vendor/`                   | Локальная фиксированная версия Three.js с лицензией     |
| `tests/`                    | Проверки логики и браузерные сценарии                   |
| `tools/`                    | Сервер разработки, статическая сборка и тестовые ролики |
| `docs/`                     | Архитектура, аудит и рекомендации                       |

## Проверки

```bash
npm ci --ignore-scripts
npm run check
npm test
npm run build
```

Для браузерных проверок дополнительно установите FFmpeg и Chromium:

```bash
npx playwright install chromium
npm run test:fixtures
npm run test:browser
```

GitHub Actions запускает эти проверки для веток `refactor/**` и pull request.
Он не разворачивает сайт и не меняет настройки рабочего GitHub Pages.

`npm run build` копирует только файлы приложения в `dist/`, без тестов и
инструментов. Проверка этой папки: `npm run preview`.

## Что проверить на своих видео

1. MP4/WebM в обычном режиме и 2:1 ролик в 360° режиме.
2. Пробел, стрелки/A/D, переход к номеру кадра, перемотку во время проигрывания.
3. Несколько файлов, повторное добавление файла, удаление активного ролика,
   очистку списка и повторный Drag & Drop.
4. Fullscreen, панели, масштабирование и перетаскивание на паузе и при проигрывании.
5. Ваши самые большие ролики и рабочие браузеры, особенно Safari и Firefox.

Поддержка контейнера не гарантирует поддержку кодека браузером. Соотношение
сторон около 2:1, как прежде, автоматически включает 360° режим. FPS со знаком
`~` означает оценку или средний FPS переменного потока; точность кадра в таких
случаях ограничена. При неизвестном FPS шаг использует 30 FPS и явно помечает
эту величину как приблизительную. На скрытой вкладке воспроизведение
приостанавливается; возобновление выполняется пользователем.

Подробности: [архитектура](docs/architecture.md) и [аудит и улучшения](docs/audit.md).
