Модульные тесты включают 3 GiB виртуальный MP4 с `moov` в конце: парсер читает
менее 2 KiB служебных данных, пропуская payload. Это проверка алгоритма на
виртуальном файле, не измерение скорости декодирования реального 3 GiB видео.

Добавлены браузерные сценарии для реальных синтетических MP4/WebM: обычная и
360° проекция, 29.97 FPS, шаг и frame jump, очередь seek, дубли, имена как
разметка, повторные переключения/очистка GPU, Drag & Drop после очистки,
восстановление после ошибки, auto-hide, fullscreen и путь GitHub Pages.
Актуальный статус прогонов доступен в Checks pull request.

## Ограничения и проверка перед переходом

Точность покадрового seek опирается на временную шкалу `HTMLVideoElement` и
FPS. Для VFR, edit lists и сложных потоков нужна отдельная индексация PTS;
новая версия явно помечает усреднённый/оценённый FPS знаком `~`. Никакой
автоматической конвертации неподдерживаемых кодеков сейчас нет.

Тестовая публикация подготовлена в `gh-pages`: исходный viewer из `main`
сохранён в корне, модульная версия — в `/preview/`. Слияние с `main` не
выполнено. Перед заменой пройти checklist из README на реальных файлах,
проверить успешный CI и сохранить возможность отката к исходному коммиту.

Справочные первичные источники для реализации:

- [Three.js VideoTexture](https://archive.threejs.org/docs/api/en/textures/VideoTexture.html)
- [Apple: time-to-sample atom](https://developer.apple.com/documentation/quicktime-file-format/time-to-sample_atom)
- [Apple: media header atom](https://developer.apple.com/documentation/quicktime-file-format/media_header_atom)
- [WebM container guidelines](https://www.webmproject.org/docs/container/)

## Исправление по результатам тестирования

Удаление полной предзагрузки ухудшало работу с сетевыми дисками. Предзагрузка
возвращена отдельным модулем, с общим лимитом кеша и LRU вместо неограниченного
накопления копий каждого добавленного файла. Для больших сетевых файлов важно
выбрать достаточный лимит или заранее скопировать их на локальный диск.

При удержании клавиши next seek выполнялся прямо в обработчике seeked до RAF
renderer. Видео успевало снова перейти в seeking, и текстура могла остаться
без готового кадра. Теперь очередь ждёт подтверждения отрисовки и сохраняет
один автоповтор. Ресурсы старого поколения отменяются, как и прежде.

Регрессионные проверки включают задержку готовности декодированных данных,
задержку renderer, 100 повторных запросов, отпускание клавиши, замену источника
во время seek/предзагрузки, LRU, отмену и отказ чтения. Браузерные сценарии
проверяют пиксели WebGL при 4-кратном замедлении CPU с кешем и без него,
удержание экранной кнопки, повторное использование копии без чтения источника
и освобождение кеша. Реальный SMB/NAS и пользовательские 4K/8K файлы
нужно дополнительно проверить в рабочем окружении пользователя.
